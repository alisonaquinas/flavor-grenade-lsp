# Markdown path targets can escape above vault root

> [!INFO] `BUG-003` · Bug · Phase 14 · Severity: `high` · Priority: `high` · Status: `done`

## Summary

Markdown target classification collapses leading `..` segments even when there
is no parent segment, so a target like `../../secret.md` can become `secret`
and be treated as a vault DocId.

---

## Reproduction Steps

1. Classify `../../secret.md` with `classifyMarkdownTarget`.
2. Observe the result is `local-document`.
3. If a vault document named `secret` exists, resolution can treat the escaped
   path as in-vault.

**Minimal reproducing vault content:**

```markdown
[Secret](../../secret.md)
```

**LSP method / trigger:** Markdown target classification during diagnostics,
definition, references, rename, or completion.

---

## Expected Behaviour

Path normalization must detect traversal underflow and classify escaping paths
as non-vault targets before resolution.

---

## Actual Behaviour

Leading parent segments are dropped by `parts.pop()`, producing an in-vault
path.

## Proposed Fix

Return a non-vault classification when dot-segment normalization would pop past
the source path root, and suppress diagnostics/resolution for that target.
