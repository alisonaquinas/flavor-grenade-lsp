# Markdown completions lose folder context for nested documents

> [!INFO] `BUG-005` · Bug · Phase 14 · Severity: `medium` · Priority: `medium` · Status: `in-progress`

## Summary

`CompletionRouter.docIdForUri()` returns only the filename stem, so Markdown
link completions in nested source documents compute relative paths from the
wrong source folder.

---

## Reproduction Steps

1. Put the current document at `file:///vault/notes/source.md`.
2. Put a target document at `notes/alpha`.
3. Request Markdown link completion after `[Alpha](`.
4. Observe completion insert text is `notes/alpha.md` instead of `alpha.md`.

**Minimal reproducing vault content:**

```markdown
[Alpha](
```

**LSP method / trigger:** `textDocument/completion`

---

## Expected Behaviour

Markdown link completions should preserve the vault-relative source DocId so
same-folder targets complete as relative Markdown paths.

---

## Actual Behaviour

The router passes `source` instead of `notes/source` to the provider.

## Proposed Fix

instead of deriving it from the filename alone.
