# File operation providers fail Nest dependency injection at server boot

> [!INFO] `BUG-015` · Bug · Phase 16 · Severity: `high` · Priority: `high` · Status: `done`

## Summary

The Phase 16 file-operation providers passed direct unit construction tests but
failed when the real Nest application context booted. The integration transport
test hung because the server process exited before answering `initialize`.

---

## Expected Behaviour

The LSP server should boot with the Phase 16 providers registered, answer
`initialize`, and complete the integration transport handshake.

---

## Actual Behaviour

`FileOperationPlanner` imported `VaultIndex` as a type-only symbol, so emitted
dependency metadata was `Object` and Nest could not resolve the constructor
argument.

---

## Violated Requirement

| Planguage Tag | Gist | Source File |
|---|---|---|
| `Parity.FileOperations.CapabilityRegistration` | Advertise and handle file-operation rename requests | [[docs/requirements/functional/ofmarkdown-parity]] |
