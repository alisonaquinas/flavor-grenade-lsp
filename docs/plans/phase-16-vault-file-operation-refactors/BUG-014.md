# File operation confinement uses workspace root instead of detected vault root

> [!INFO] `BUG-014` · Bug · Phase 16 · Severity: `high` · Priority: `high` · Status: `done`

## Summary

`workspace/willRenameFiles` and `workspace/didRenameFiles` derive the
confinement root from `LifecycleState.rootUri`. When the workspace root is
broader than the detected vault root, the planner can accept paths outside the
vault but inside the workspace.

---

## Expected Behaviour

File-operation planning should use the detected vault root returned by
`VaultDetector`, falling back to `null` when no vault root is available.

---

## Actual Behaviour

The handler passes the workspace root directly to `FileOperationPlanner`.

---

## Violated Requirement

| Planguage Tag | Gist | Source File |
|---|---|---|
| `Security.Vault.PathConfinement` | Canonicalize and vault-root-check every old and new path | [[requirements/security/vault-confinement]] |
| `Security.Vault.RenameConfinement` | Cancel rename and move edits that escape the vault root | [[requirements/security/vault-confinement]] |
