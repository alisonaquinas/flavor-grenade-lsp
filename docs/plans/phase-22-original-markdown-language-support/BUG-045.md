# Ignore Frontmatter When Scanning Original Setext Headings

> [!SUCCESS] `BUG-045` - Bug - Phase 22 - Severity: `medium` - Status: `done`

## Finding

Step I full unit testing found `OFMParser integration > extracts headings`
failing after Phase 22 setext heading support was added. The setext scanner can
interpret the YAML frontmatter closing `---` as a setext underline for the
previous frontmatter line, causing a synthetic heading to appear before the
first document heading.

## Fix Plan

- Pass the parsed body offset into heading scanning.
- Suppress ATX and setext heading candidates that start before the Markdown
  body.
- Add or update regression coverage so frontmatter delimiters cannot become
  headings.
