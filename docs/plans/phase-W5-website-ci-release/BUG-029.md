# Support Independent Website Release Tags

> [!WARNING] `BUG-029` · Bug · Phase W5 · Severity: `high` · Status: `done`

## Summary

The website Pages workflow supports `v*.*.*` release tags, but the repository CI
publish job also wakes on `v*` tags. A website-only release needs an
independent `site-vX.Y.Z` tag path so Pages can deploy without attempting an npm
package publish for the root server package.

## Reproduction

1. Inspect `.github/workflows/ci.yml`.
2. Observe the `publish` job condition: `startsWith(github.ref, 'refs/tags/v')`.
3. Inspect `.github/workflows/website-pages.yml`.
4. Observe that the Pages workflow does not currently accept `site-v*.*.*`
   tags.

## Expected Behavior

The website release workflow should support `site-vX.Y.Z` production tags and
`site-vX.Y.Z-test.N` test tags, while keeping production deploys guarded by
`origin/main`.

## Actual Behavior

The Pages workflow is tied to `v*.*.*` tags, which are shared with root package
release automation.

## Violated Requirement

`Website.CICD.PagesDeployment`: Website Pages deployment is tag triggered,
main-branch guarded, minimally permissioned, and environment protected.

## Proposed Fix

- Add `site-v*.*.*` and `site-v*.*.*-test*` tag triggers to
  `website-pages.yml`.
- Extend the validation guard to allow either `vX.Y.Z` or `site-vX.Y.Z`, with
  optional test suffixes.
- Update the Pages workflow regression test so independent website release tags
  cannot be removed silently.
