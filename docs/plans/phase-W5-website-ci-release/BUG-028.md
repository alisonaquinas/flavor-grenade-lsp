# Use GitHub Glob-Safe Website Release Tag Triggers

> [!WARNING] `BUG-028` · Bug · Phase W5 · Severity: `high` · Status: `done`

## Summary

The website Pages workflow used a regex-shaped production tag filter,
`v[0-9]+.[0-9]+.[0-9]+`, inside a GitHub Actions `tags` filter. GitHub Actions
tag filters use glob patterns, so the workflow may not reliably run for normal
release tags such as `v1.2.3`.

## Reproduction

1. Inspect `.github/workflows/website-pages.yml`.
2. Compare the `on.push.tags` value against GitHub Actions workflow syntax for
   tag filters.
3. Observe that the pattern is written like a regular expression instead of a
   GitHub tag glob.

## Expected Behavior

The website Pages workflow should trigger for normal release tags and test tags,
then validate the exact release-tag shape inside the workflow before build or
deploy.

## Actual Behavior

The workflow uses `v[0-9]+.[0-9]+.[0-9]+`, which is not the same as a semantic
version regular expression in GitHub Actions tag-filter syntax.

## Violated Requirement

`Website.CICD.PagesDeployment`: Website Pages deployment is tag triggered,
main-branch guarded, minimally permissioned, and environment protected.

## Proposed Fix

- Use a broad GitHub Actions glob tag trigger such as `v*.*.*`.
- Keep test tags covered by the same trigger.
- Add an explicit shell validation step that enforces the intended semantic
  version or test-tag pattern before build and deploy.
- Update `website/tests/pages-workflow.test.ts` as the regression guard.
