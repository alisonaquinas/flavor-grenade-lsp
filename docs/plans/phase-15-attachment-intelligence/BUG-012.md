# Scanned image attachments do not populate cheap dimensions

> [!INFO] `BUG-012` · Bug · Phase 15 · Severity: `low` · Priority: `medium` · Status: `red`

## Summary

`AttachmentEntry.dimensions` is documented and rendered by hover, but real
scanner and watcher paths only populate path, URI, extension, kind, and size.
Only tests that manually inject attachment metadata can show dimensions.

---

## Expected Behaviour

Vault scanning and non-document file watcher events should store image
dimensions when they can be read cheaply, without blocking or failing
attachment indexing when dimensions are unavailable.

---

## Actual Behaviour

Real PNG image attachments are indexed without dimensions, so hover cannot show
the metadata promised by the Phase 15 requirements.
