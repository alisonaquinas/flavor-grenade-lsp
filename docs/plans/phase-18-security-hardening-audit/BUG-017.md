# Enforce Frontmatter YAML Size And Alias Limits

> [!INFO] `BUG-017` · Bug · Phase 18 · Severity: `high` · Priority: `high` · Status: `in-review`

## Summary

`FrontmatterParser` calls `yamlLoad()` on the entire frontmatter block with
`CORE_SCHEMA`, but it does not enforce the documented 64 KB size limit or alias
cap before parsing.

---

## Reproduction Steps

1. Open a vault document whose frontmatter body exceeds 64 KB.
2. Include many YAML anchors or aliases.
3. Observe that parsing is attempted instead of being rejected as malformed frontmatter.

**Minimal reproducing vault content:**

```markdown
---
a: &a ["x"]
b: *a
---
# Alpha
```

**LSP method / trigger:** `textDocument/didOpen`, initial vault scan

---

## Expected Behaviour

Oversized or over-aliased YAML frontmatter is treated as malformed frontmatter
without unbounded parser work.

---

## Actual Behaviour

The parser slices the full YAML block and passes it directly to `yamlLoad()`.

## Proposed Fix

Reject frontmatter above 64 KB before YAML parsing, configure supported
`js-yaml` alias protections if available, and add an explicit post-parse alias
budget guard if the library option cannot express the policy.
