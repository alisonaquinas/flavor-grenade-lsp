# Enforce Vault Scan File-Count Limits

> [!INFO] `BUG-019` · Bug · Phase 18 · Severity: `high` · Priority: `medium` · Status: `triaged`

## Summary

`VaultScanner.walkAndIndex()` recursively indexes every readable file under the
vault root with no configurable file-count cap or client warning when the
documented limit is exceeded.

---

## Reproduction Steps

1. Create a vault containing more than 50,000 files.
2. Start the server with that vault as `rootUri`.
3. Observe that scanning continues instead of stopping at the configured budget.

**Minimal reproducing vault content:**

```markdown
# Repeat this file past the configured scan limit
```

**LSP method / trigger:** `initialized`

---

## Expected Behaviour

Initial indexing stops at the configured limit and notifies the client that the
vault exceeded the indexing budget.

---

## Actual Behaviour

The scanner has no file counter, directory budget, or warning path.

---

## Proposed Fix

Add scanner budget configuration with a default 50,000-file cap, stop walking
after the cap, and send a bounded client notification describing the limit.
