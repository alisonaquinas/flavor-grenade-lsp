# Keep Adversarial Parser Safety Test Inside Budget

> [!INFO] `BUG-023` · Bug · Phase 18 · Severity: `high` · Priority: `high` · Status: `in-review`

## Summary

The Phase 18 verification sweep found that an adversarial delimiter-only
document can exceed the parser safety budget on Windows.

---

## Reproduction Steps

1. Run `bun test src/parser/`.
2. Observe `OFMParser safety budgets > handles adversarial unmatched delimiters inside the parser budget`.
3. The test fails when elapsed parse time is greater than 200 ms.

**Minimal reproducing vault content:**

```markdown
[[[[[... 10,000 opening brackets ... ]]]]]
```

**LSP method / trigger:** document parse during open/change/indexing.

---

## Expected Behaviour

Parser safety regression coverage stays inside the documented budget so hostile
input does not make verification flaky or allow slow parser paths to ship.

---

## Actual Behaviour

`bun test src/parser/` failed with elapsed parse time `571.972` ms for the
adversarial unmatched delimiter case.

## Proposed Fix

Short-circuit wiki-link parsing when the document has no `]]` close marker, and
make inline math scanning skip over known display-math regions in one step
instead of checking each `$` against every display region.
