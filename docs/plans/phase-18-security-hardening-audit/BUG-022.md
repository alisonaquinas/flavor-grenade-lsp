# Pin Dependency Specifiers And Add Range Lint

> [!INFO] `BUG-022` · Bug · Phase 18 · Severity: `high` · Priority: `high` · Status: `in-review`

## Summary

`package.json` and `extension/package.json` still contain `^` and `~`
dependency specifiers, and CI has no manifest-range lint to enforce exact
pinning.

---

## Reproduction Steps

1. Run `Select-String -Path package.json,extension/package.json -Pattern '"[~^][^"]+"'`.
2. Observe range specifiers in runtime and development dependencies.
3. Inspect CI and observe no exact-pinning check.

**Minimal reproducing vault content:**

```markdown
# Not applicable
```

**LSP method / trigger:** dependency installation in CI or release workflows

---

## Expected Behaviour

All package dependency specifiers are exact, lockfiles are refreshed, and CI
fails if a new range specifier is introduced.

---

## Actual Behaviour

The manifests include range specifiers such as `^11.1.19`, `^9.0.1`, and
`~1.82.0`. The current advisory scans reported no vulnerabilities, but the
exact-pinning policy is not enforced.

## Proposed Fix

Replace all dependency ranges with exact versions, refresh root and extension
lockfiles with frozen installs where possible, add a dependency range lint
script, and wire it into CI.
