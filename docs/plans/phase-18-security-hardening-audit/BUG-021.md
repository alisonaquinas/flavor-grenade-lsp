# Reject Prototype-Polluting JSON-RPC Payloads

> [!INFO] `BUG-021` · Bug · Phase 18 · Severity: `high` · Priority: `medium` · Status: `in-progress`

## Summary

`JsonRpcDispatcher` parses request bodies with `JSON.parse()` and forwards
params to handlers without rejecting dangerous object keys such as `__proto__`
or `constructor.prototype`.

---

## Reproduction Steps

1. Send any JSON-RPC request with params containing `{"__proto__":{"polluted":true}}`.
2. Route the request through `JsonRpcDispatcher.dispatch()`.
3. Observe that no schema validation rejects the dangerous key before handler dispatch.

**Minimal reproducing vault content:**

```markdown
# Alpha
```

**LSP method / trigger:** any JSON-RPC request with object params

---

## Expected Behaviour

Dangerous prototype keys are rejected before any handler receives request
params, and `Object.prototype` remains unmodified.

---

## Actual Behaviour

The dispatcher only catches JSON parse errors and method lookup errors.

## Proposed Fix

Add a recursive plain-object validator in the dispatcher that rejects
`__proto__`, `prototype`, and `constructor` keys where they can influence
object prototypes. Return InvalidParams for requests and silently drop invalid
notifications.
