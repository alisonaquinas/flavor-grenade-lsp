# Prove And Enforce Symlink Realpath Confinement

> [!INFO] `BUG-020` · Bug · Phase 18 · Severity: `high` · Priority: `high` · Status: `triaged`

## Summary

The codebase has no `realpath`-based symlink confinement guard or passing test
for out-of-vault symlink targets, so `Security.Vault.SymlinkConfinement` remains
unproved.

---

## Reproduction Steps

1. Create a symlink inside a test vault that points to a Markdown file outside the vault.
2. Start indexing or request navigation to the symlink path.
3. Observe that no dedicated realpath confinement test proves the target is treated as missing.

**Minimal reproducing vault content:**

```markdown
[[linked-secret]]
```

**LSP method / trigger:** initial vault scan, definition, diagnostics

---

## Expected Behaviour

Out-of-vault symlink targets are treated as non-existent and diagnostics remain
FG001/FG004 rather than indexing or navigating outside the vault.

---

## Actual Behaviour

The scanner uses `Dirent.isFile()` and path-prefix checks, but there is no
central `realpath` guard or test proving symlink target confinement across
scan, resolution, and file-operation paths.

## Proposed Fix

Add a shared `confineToVaultRoot()` helper that compares both normalized path
and `fs.realpath()` result to the vault root. Use it before indexing, resolving
attachment metadata, and planning file operations.
